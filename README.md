# مقارنة بين نمط الجلسات (Stateful) والنمط بدون جلسات (Stateless) في خوادم MCP

| وجه المقارنة | نمط الجلسات (Stateful) | النمط بدون جلسات (Stateless) |
| :--- | :--- | :--- |
| **طريقة الاتصال** | `POST` للأوامر + `GET` لـ SSE + `DELETE` للإغلاق | `POST` فقط لكل الطلبات |
| **إدارة الجلسات** | يتطلب تخزين الـ Transports في الذاكرة (`transports[sid]`) | لا يتم تخزين أي جلسة (`sessionId: undefined`) |
| **عمر السيرفر** | يبقى كائن السيرفر حياً طوال فترة فتح الجلسة | يُنشأ السيرفر ويُغلق في أجزاء من الثانية مع كل طلب |
| **إرسال التحديثات** | **ممكن:** السيرفر يستطيع دفع تحديثات فورية عبر SSE | **غير ممكن:** السيرفر يرد فقط عندما يُطلب منه |
| **التقسيم والتوسع (Scaling)** | **صعب:** إذا كان لديك سيرفرات سحابية متعددة، يجب توجيه العميل لنفس الخادم الذي يحفظ الجلسة في الذاكرة (Sticky Sessions). | **سهل جداً:** أي سيرفر خلف الـ Load Balancer يمكنه معالجة الطلب مباشرة. |

---

## متى تستخدم كلاً منهما؟

### 1. استخدم نمط **Stateless**:
إذا كنت تبني **MCP Server** ليعمل مع Gemini أو أدوات سحابية/Docker، حيث أن معظم المحركات الحديثة تفضل `POST` المستقل لسهولة الأداء والتوسع وعدم الحاجة لاتصالات دائمة.

### 2. استخدم نمط **Stateful**:
إذا كنت تبني تطبيقاً محلياً على جهازك (مثل اتصال MCP خفيف بـ Claude Desktop) أو تطبيقاً يحتاج إلى بث إشعارات في الوقت الفعلي (**Real-time Streaming**) من السيرفر إلى العميل.
